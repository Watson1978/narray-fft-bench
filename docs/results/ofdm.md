# F. OFDM の変調と復調

QPSK のビットを、`ifft` とサイクリックプレフィックス（CP、長さ N/8）で送り、多重波の通信路（5 タップ、エネルギー 1）を `fftconvolve` で通し、CP を外して `fft` と 1 タップの等化 `Y / H`（`H = fft(h, n: N)`）で戻す。シンボルは `[シンボル数, N]` のまま、最後の軸に沿って 1 回で変換する。2026-10-18、cumo 0.14.0（`vendor/cumo-0.14.0/`）、CuPy 14.2.0、numpy 2.5.3、scipy 1.18.1、numo-pocketfft 0.7.0、RTX 5070 Ti Laptop（12 GB）。

## 入力

- small: N = 64、1000 シンボル（128000 ビット）、通信路 1 本、雑音（単位分散の複素数、`[1000, N + CP]`）。Eb/N0 は 0、2、4、6、8、10 dB の 6 点で、同じ雑音を Eb/N0 に合わせて縮めて使う。
- 計測用: N = 64、256、1024 × 1000 本と 10000 本（`n<N>_s<本数>`）。雑音は入れていない。
- 通信路は、シンボルごとに独立に掛ける。`fftconvolve(x, h.reshape(1, taps))` の 2 次元の畳み込みで、行ごとの畳み込みになる。先頭の過渡は CP が吸収し、シンボルの後ろにはみ出た分は捨てる。

## 関門

- `<norm>.bit_errors`: 雑音なしで、送ったビットがすべて戻る（違ったビットの数が 0）。`norm` は `backward`、`ortho`、`forward` の 3 つで、送受で同じ `norm:` を使う。判定は z / |z| の符号から行うので、0 と 1 がちょうどの値で出る。
- `<norm>.parseval`: 送信の `x = ifft(X, norm:)` で、Σ|x|² = c Σ|X|²（c は backward が 1/N、ortho が 1、forward が N）の相対差。tol は fp64 で 5.6e-14（Numo の 5.57e-15 の 10 倍）、fp32 で 6.1e-7（numpy、CuPy、Cumo の 6.10e-8 の 10 倍）。
- `awgn.<dB>dB.sigmas`: 雑音ありの誤りの数と、その期待値との差が、二項分布の標準偏差の 3 倍以内。
- `fftshift.frequencies`: `fftshift(fftfreq(N))` が、−1/2 から昇順に並ぶ（違う要素の数が 0）。
- `fftshift.dc_center`: 等化したシンボルを `fftshift(…, axes: [-1])` で中心周波数の順に並べると、DC のサブキャリアが真ん中（N/2）に来る。
- `values`: 雑音なしの誤りの数（3 つの norm の合計）、通信路の平均の利得 Σ|H_k|²/N、各 Eb/N0 の誤りの数。

**BER の期待値は、サブキャリアごとの QPSK の誤り率の平均にした。** 計画は「QPSK の理論値 ½ erfc(√(Eb/N0)) に対して 3σ 以内」としていたが、これは平坦な通信路（AWGN だけ）の式。多重波の通信路で 1 タップの等化をすると、サブキャリア k の SNR は |H_k|² 倍になるので、ビット誤り率は p_k = ½ erfc(√(|H_k|²·Eb/N0)) になる。期待値は Σ_k 2S·p_k（S はシンボル数）、分散は Σ_k 2S·p_k(1 − p_k) とした。|H_k| がすべて 1 なら、計画の式に戻る。計画の式のままだと、10 dB での期待値は 0.5 個で、観測した 1234 個と合わない。

送信のシンボルは、エネルギー 1 の QPSK（Eb = 1/2）。複素数の雑音の分散を 1 / (2 Eb/N0) にすると、`ortho` の `fft` のあとも同じ分散になる。CP の分のエネルギーは Eb に数えない（受信で捨てるので、サブキャリアの SNR に効かない）。

| `fftshift`（2 つ） | 0 | 0 | 0 | 0 | 0 | 0 | 0 |

- 4 実装とも、fp64 と fp32 で 14 個の関門がすべて通る。誤りの数は、fp32 も含めて 7 通りでビットまで同じ。`values` は、fp64 の 4 実装で 1e-9 の内側、fp32 の 3 実装で 1e-3 の内側に揃う（`script/compare_gates.rb`）。
- 通信路の平均の利得 Σ|H_k|²/N は 1（タップのエネルギーが 1 なので、Parseval から）。
- 雑音なしの誤りが 0 なのは、3 つの norm のすべてで同じ。送受で norm を揃えれば、スケールは打ち消される。
- Numo シムと `Cumo::FFT` の直接比較（`test/test_parity.rb` の F の呼び出し 13 種）の差は、最大 1.61e-15（2 次元のバッチの `fftconvolve`）。これまでの最大（D の 1.42e-15）を超えたので、tol を 1.6e-14 にした。

## 速さ

ステップは 2 種類。`batch` は、`[本数, N]` のシンボル全部を 1 回で送受する（`ifft(…, norm: 'ortho')`、CP の付加、CP の除去、`fft(…, norm: 'ortho')`、`/ H`）。計画の表の見出し（「fft + ifft + 等化」）に合わせ、通信路の `fftconvolve` と雑音と判定は入れない。2 次元のバッチの `fftconvolve` は、バッチの軸にも変換をかけるので、「小さい変換を大量に」の計測にならないため。`single` は、同じことを 1 本ずつ 10000 回行う（N = 64）。比は numpy ÷ Numo（CuPy ÷ Cumo）で、1 を超えれば Ruby 側が速い。後ろの n/10 は、10 ラウンドのうち比が 1 を超えたラウンドの数。

- 幅が 5% を超えた定常の系列は、生の値をラウンド順に見て、どれも 2 つの群に分かれず、ばらつきが連続していた。

#### batch で Cumo が遅い理由（64 × 10000、fp32）

nsys で `--inner` 1000 と 3000 の差を取ると、1 ステップのカーネルの時間の合計は Cumo が 52 µs、CuPy が 44 µs で、差は小さい（割り算は、`ifft` と `fft` の後の 1/√N が 2 本と等化が 1 本で、Cumo が 22 µs、CuPy が 18 µs）。区間内の同期は、両者とも 0 回。ところが計測の表では、Cumo の 1 ステップは 99 µs かかる。

**差の大半は、Ruby の GC だった。** 同じステップを 3000 回回して `GC.stat` を数えると、次のようになった（単発、cumo 0.14.0）。

| 条件 | ms/ステップ | 3000 ステップ中の GC | GC の時間（1 ステップあたり） |
|---|---|---|---|
| 64 × 1000 | 0.035 | minor 231 回 | 7 µs |
| 64 × 10000 | 0.086 | minor 2143 回 | 57 µs |
| 1024 × 1000 | 0.118 | minor 3000 回 | 75 µs |

cumo は、GPU のメモリの確保と解放を `rb_gc_adjust_memory_usage` で Ruby に知らせている（`ext/cumo/narray/narray.c`）。そのため、確保の量が malloc の上限（既定で 16 MB）を超えるたびに minor GC が起き、一時配列がメモリプールに戻る、と見ている。64 × 10000 本の fp32 の配列は 1 本 5.8 MB で、1 ステップで 5 本ほど作るので、ほぼ毎ステップ GC が走る。CuPy は参照が切れたときにすぐ返すので、GC を待たない。

- `RUBY_GC_MALLOC_LIMIT=268435456`（256 MB）にすると、GC は 39 回（minor 20、major 19）に減るが、1 ステップは 0.086 ms から 0.112 ms に遅くなった。GC が減った分、一時配列がプールに戻らず、毎ステップ新しいメモリを使うためと見ている（E の「Cumo が遅い理由」の 3 と同じ）。
- ステップの一時配列（`ifft` の結果、CP を付けた配列、`fft` の結果、等化の結果）を、使い終えた時点で `NArray#free` すると、GC は 1429 回から 400 回に減り、1 ステップは 0.085 ms から 0.059 ms になった（3 回中 2 回。1 回は 0.086 ms）。CuPy の 0.058 ms と並ぶ。1024 × 1000 本では、0.120 ms から 0.102〜0.118 ms になった（CuPy は 0.098 ms）。`Cumo::FFT` の中の一時配列は解放していないので、GC は 0 にならない。
