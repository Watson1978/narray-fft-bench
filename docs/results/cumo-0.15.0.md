# cumo 0.15.0

2026-11-03、cumo 0.15.0（2026-11-02 リリース、タグ `v0.15.0` = `ee6facf2`）を `vendor/cumo-0.15.0/` に入れ、0.14.1 からの回帰が無いかを確かめた。回帰は無かったので、既定をこれに替えた。`Cumo::FFT` と `Cumo::Pocketfft` は変わっていない（gem の `lib/cumo/` の Ruby のファイルも、`version.rb` のほかは同じ）。0.14.1 からの変更のうち、題材に関わりうるのは次のもの。

- #634: `sum`、`mean`、`max`、`min` とベクトルの `dot` を、別のカーネルのモジュールに分けた。型ごとに最初の 1 回が速くなる。ほかの縮約（`max_index` など）は、残りのモジュールに入る。
- #635、#636: `cumsum`、`cumprod`、`sort`、`median`、`sort_index` の最初の 1 回が速くなった。題材は使わない。
- #641: 添字の処理を書き直した（空の配列の添字、負のステップの範囲）。
- #642、#638、#643: 行の格納中の GC の修正、`RObject` のバイト列のメソッドの削除、`Range#%` の再定義の警告の修正。

## 正しさ

- 7 題材の関門の値と `values` は、small の fp64 と fp32、E の n1024 で、0.14.1 とビットまで同じだった（`script/gate.rb` の JSON の `problems` を比べた）。D の fp32 の small は、両方の版で同じ値で外れる（[bignum_mul.md](bignum_mul.md) に書いた既知の挙動）。
- `rake test` は、CPU でも `GPU=1` でも、0.15.0 で 65 件すべて通った。

- 同じビルドでも、日によって数字が動く。0.14.1 の B の N = 2048 は、2026-10-22 には 11.9 ms、この日は 10.6 ms だった。版の比べは、同じラウンドの中だけで行う。

## C の `axes01` の 256³ が 2 つの群に分かれた

0.15.0 は、Ruby と対照の 20 回のうち 15 回が 2.41〜2.55 ms、5 回が 3.10〜3.60 ms だった。0.14.1 は 10 回とも 3.10〜3.59 ms だった。比の中央値は 1.289 だが、群の間に落ちた値なので、速くなったとは読まない。0.15.0 の遅い群は 0.14.1 と同じ範囲なので、回帰でもない。

同じステップを 300 回繰り返し、`GC.stat` の差を回数で割った（単発、fp32、2 つの版を交互に 4 回ずつ）。

| 版 | 1 ステップ（ms） | GC の時間（ms / ステップ） | minor | major |
|---|---|---|---|---|
| 0.15.0 | 2.62〜3.31 | 2.19〜2.25 | 6.0 | 1.0 |
| 0.14.1 | 3.20〜3.40 | 2.96〜3.06 | 5.5 | 1.5 |

- major GC のきっかけは、どちらの版でも oldmalloc（古い世代の malloc の増分が上限の 128 MB を超えたもの。cumo の GPU のメモリの申告もここに入る）だった。
- 同じ 0.15.0 でも、プロセスによって major が 1 ステップに 1 回か 1.5 回かに分かれる。別に 200 回ずつ 2 回流したときは、0.15.0 の 1 回が 1.5 回の側に入り、0.14.1 は 2 回とも 1.5 回だった。GC の周期がどこに嵌まるかの違いで、ビルドが GC を変えたのではないと見ている。0.15.0 がなぜ 1 回の側に入りやすいかは、確かめていない。
- 1 回の側に入った 0.15.0 でも、1 ステップは 2.62〜3.31 ms とばらついた。群の分かれ方が GC の回数だけで決まるのかも、確かめていない。

## 再現

```
CUMO_NVCC_GENERATE_CODE=arch=compute_120,code=sm_120 gem install cumo -v 0.15.0 --no-document --ignore-dependencies --install-dir vendor/cumo-0.15.0
GPU=1 DTYPE=fp32 CUMO_LIB=$PWD/vendor/cumo-0.14.1/gems/cumo-0.14.1/lib ruby script/gate.rb --out tmp/gates/cumo-0.14.1.json
GPU=1 DTYPE=fp32 ruby script/gate.rb --out tmp/gates/cumo-0.15.0.json
```

交互の計測は、`bench/conditions.tsv` の行の Ruby のコマンドの前に、2 つの版の `CUMO_LIB=<lib のパス>` を付けて Ruby と Python の列に置き、`bench/run.sh` に渡す（`bench/aggregate.py --labels 0.15.0,0.14.1`）。
